# Выпуск НейроТипировщика на indikov.ru

## Что публиковать

После `npm run build` содержимое папки `dist` нужно положить в каталог `sociotyper` репозитория GitHub Pages. Публикуется именно содержимое `dist`, а не сама внешняя папка. В собранном `index.html` адреса начинаются с `/sociotyper/assets/`.

## Какой вариант API выбрать

Продакшн-вариант: маршрут Cloudflare `indikov.ru/api/typist/*`. Клиент уже обращается к `/api/typist`, поэтому собирать его с `VITE_TYPIST_API_BASE` не требуется.

Запасной вариант: не создавать маршрут, а перед сборкой задать полный адрес постоянного Worker:

```powershell
$env:VITE_TYPIST_API_BASE='https://ВАШ-WORKER.ВАШ-СУБДОМЕН.workers.dev/api/typist'
npm run build
```

Оба способа одновременно не нужны.

## Почему одного статического сайта недостаточно даже для своего ключа

Поле ключа находится на главной, но запрос проходит через Worker: он управляет очередью, событиями и восстановлением. В новой схеме ключ временно хранится зашифрованным в задании D1, чтобы анализ продолжался после закрытия вкладки. После завершения, ошибки или отмены вход удаляется; истёкшие задания очищаются ежечасно. Ключи не входят в Workflow payload, клиентскую сборку или журналы.

Рабочий production-конфиг находится в `cloudflare-worker/wrangler.production.jsonc`. В нём уже указан созданный D1 `indikov-typist` и маршрут `indikov.ru/api/typist/*`. R2 в аккаунте пока не включён, поэтому отладочное сохранение временно выключено; анализ, BYOK, лимиты и коды от этого не зависят.

## Проверка после публикации

Перед клиентом развернуть Worker: применить `schema.sql` (при первом запуске) и `jobs-schema.sql` в D1; добавить случайный `JOB_ENCRYPTION_KEY` через `wrangler secret put`; выполнить `wrangler deploy --config wrangler.production.jsonc`. Конфигурация создаёт Workflow и плановую очистку. Не менять ключ шифрования при наличии незавершённых заданий. Для встроенных попыток отдельно нужен `KNYAZEV_API_KEY`. Без него работает только подключённый пользователем API; `/health` честно возвращает `includedReady: false`. Для нового клиента обязательно `jobsReady: true`.

1. `https://indikov.ru/sociotyper/` — интерфейс, не белая страница.
2. `https://indikov.ru/api/typist/health` — JSON с `"ok": true`.
3. На главной вставить ограниченный Knyazev-ключ и нажать «Подключить».
4. Убедиться, что MiniMax 2.7 проходит проверку.
5. Выполнить одно типирование с согласием на отладку и найти его `traceId` в Cloudflare Logs.

## Что удалить или не загружать

- старые файлы из удалённой папки `sociotyper/assets/` — их заменяет новый набор с хешированными именами;
- старый `sociotyper/index.html` — заменить новым;
- любые `.wrangler*`, `node_modules`, исходные `.tsx`, локальные тесты и ZIP из папки сайта;
- любой когда-либо опубликованный API-ключ — отозвать у провайдера.

Не удалять остальные разделы сайта и DNS-записи. В GitHub меняется только каталог `sociotyper`.
