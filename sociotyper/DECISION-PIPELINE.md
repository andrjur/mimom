# Как НейроТипировщик принимает решение

## 1. Какие данные входят в одну сессию человека

Для каждого участника создаётся отдельный `sessionId`. Внутри сессии хранятся имя, текст анкеты, текстовые файлы, исходные аудиофайлы, подсказка для аудиомодели, локальный черновик, ответ ИИ, остаток попыток и вопросов. Материалы другого участника в запрос не добавляются.

Текстовые файлы добавляются к анкете с заголовком файла. Аудио хранится отдельно. Если OMNI-модель не настроена, DeepSeek получает не звук, а честную служебную отметку: аудио приложено, но не расшифровано; делать выводы об интонации нельзя.

## 2. Что происходит сразу после нажатия «Анализировать»

Одновременно запускаются две ветки:

1. Браузерный локальный алгоритм считает словесные маркеры по четырём базовым шкалам. Он нужен только как предварительный ответ после 40 секунд или при сетевой ошибке.
2. Worker уменьшает счётчик попыток, выбирает провайдера и запускает ИИ-пайплайн.

У каждого анализа появляется случайный `traceId`. Он одинаков для всех обращений к моделям внутри одного анализа.

## 3. Локальный алгоритм

Он нормализует регистр и `ё/е`, затем считает заранее заданные слова по четырём парам:

- экстраверсия / интроверсия;
- логика / этика;
- интуиция / сенсорика;
- рациональность / иррациональность.

Для каждой шкалы выбирается полюс с большим числом маркеров. Уверенность зависит от разницы счёта. После этого все 16 ТИМов получают баллы за совпадение своих четырёх базовых признаков с выбранными полюсами. Верхняя строка становится временной основной версией.

Это не полноценное типирование: алгоритм не понимает иронию, отрицание, контекст, причины поведения и звук. Поэтому его уверенность ограничена, а таблица слов показывает все сработавшие маркеры.

Если содержательных слов меньше восьми, алгоритм признаёт, что решения нет. Он запускает браузерный криптографический генератор случайных чисел, выбирает временный ТИМ и ставит 8%. На экране появляется большая плашка, что это генератор случайной заглушки. Результат сохраняется внутри сессии, поэтому уже показанная заглушка не прыгает при каждом перерисовывании страницы.

## 4. Подготовка контекста Worker

Worker создаёт единый источник:

```text
ТЕКСТ УЧАСТНИКА:
...

АУДИО/ТРАНСКРИПТ:
...

ЖЁСТКИЕ ОГРАНИЧЕНИЯ ПОЛЬЗОВАТЕЛЯ:
...

ПРЕДПОЧТЕНИЕ ПОЛЬЗОВАТЕЛЯ:
...
```

Замки считаются непреложными ограничениями. Выбранный пользователем ТИМ — не доказательство и не замок: модель обязана отдельно проверить, подтверждается ли эта версия.

## 5. Четыре ИИ-этапа

Для обычных недорогих моделей первые три обращения идут параллельно.

### Наблюдения

Модель не типирует. Она извлекает факты, короткие цитаты, способы выбора, реакцию на неопределённость и недостающие данные. Цель — не дать итоговой модели выдать интерпретацию за наблюдение.

### Конкурирующие гипотезы

Другая модель выбирает основную версию и минимум две альтернативы, оценивает дихотомии и перечисляет неопределённости. Выбирать можно только из фиксированного списка 16 ТИМов.

### Критик

Третье обращение специально ищет ошибки: социальную роль, профессию, настроение, выученный жаргон, желаемый образ и другие ложные признаки. Критик предлагает контргипотезы и вопросы, которые могут их развести.

### Итог

Четвёртая модель получает исходный материал плюс JSON трёх предыдущих этапов. Она должна вернуть основной ТИМ, альтернативы, уверенность, дихотомии с доказательствами, слова/цитаты и сомнения. Это единственный ответ, который становится итоговым типированием.

Для сильной Anthropic-модели предусмотрен единый глубокий запрос: те же четыре проверки выполняются внутри одного обращения, потому что такой модели полезнее цель и границы, чем четыре отдельных коротких промпта.

## 6. Как выбирается ТИМ

Решение принимает итоговая модель, но её ответ проходит проверки приложения:

1. Аббревиатура должна входить в список 16 допустимых ТИМов.
2. Уверенность приводится к диапазону 0–100.
3. Уровень показывается словами: данных недостаточно, низкая, средняя или высокая уверенность.
4. Альтернативы и сомнения сохраняются, а не скрываются.
5. Заблокированные пользователем признаки уже присутствуют в контексте как жёсткие ограничения.

Проценты — не доля типа в личности и не объективная вероятность в статистическом смысле. Это калиброванная самооценка конкретного ответа модели относительно предоставленного материала.

## 7. Когда запускается настоящий генератор случайности

Worker запускает криптографический генератор случайных чисел, если одновременно выполнены условия:

- модель не вернула допустимый ТИМ либо признала полную неопределённость с уверенностью не выше 10%; или нет ни текста, ни доступной расшифровки аудио;
- пользователь не выбрал предпочитаемый ТИМ;
- пользователь не поставил замки на признаки.

Случайная версия получает уверенность 0%, флаг `randomFallback=true` и отдельное предупреждение. Она нужна только для того, чтобы пользователь всё равно попал в красивый экран результата и мог изучить справочники. Она не участвует в мэтчинге как диагностически надёжный вывод.

## 8. Переключение локального ответа на ИИ

Если ИИ не ответил за 40 секунд, показывается локальный черновик. Запрос не отменяется. На экране продолжает двигаться индикатор фоновой работы. Когда ответ приходит, начинается пятисекундный отсчёт; пользователь может отменить автоматическое переключение и открыть ответ ИИ позже кнопкой.

## 9. Что пишется в диагностические логи

Для каждого этапа пишутся структурированные события:

- `typist.analysis.start` — размеры текста, список файлов без содержимого ключей, замки, предпочтение, провайдер и модель;
- `typist.model.request` — этап, модель, размер промпта и полный промпт при отладочном согласии;
- `typist.model.response` — длительность, usage провайдера и полный разобранный JSON при отладочном согласии;
- `typist.model.error` — этап, модель и безопасный текст ошибки;
- `typist.random_fallback` — причина запуска случайности и выбранная заглушка;
- `typist.analysis.complete` — итоговый ТИМ, уверенность и признак случайности.

API-ключи не входят ни в одно событие. Все события одного анализа ищутся по `traceId`.
