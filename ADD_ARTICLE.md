# Как написать и добавить статью

Статьи лежат в папке `_posts`. GitHub Pages сам превращает Markdown-файл в страницу, добавляет её в общий список и публикует на `indikov.ru/articles/`.

## 1. Сначала сформулируйте задачу читателя

Одна статья отвечает на один вопрос. Перед текстом заполните три строки:

- **читатель:** кто открыл материал;
- **ситуация:** что у него происходит сейчас;
- **результат:** что он сможет сделать после чтения.

Пример: «Родитель восьмиклассника не понимает, где у ребёнка пробелы. После статьи он проведёт короткую проверку и выберет одну тему на неделю».

## 2. Соберите скелет по принципу «ясно и понятно»

1. Заголовок обещает конкретную пользу, а не интригует любой ценой.
2. Первый абзац называет ситуацию читателя.
3. Подзаголовки сообщают вывод раздела. По ним должен быть понятен весь ход статьи.
4. Каждый абзац выражает одну мысль.
5. Абстракцию подкрепляет пример, наблюдение или маленький эксперимент.
6. В конце — один следующий шаг, который можно выполнить сегодня.

Хороший объём для сайта — 4–8 тысяч знаков. Если тема больше, лучше сделать цикл из двух или трёх материалов.

## 3. Создайте файл в GitHub

1. Откройте репозиторий `andrjur/mimom`.
2. Перейдите в папку `_posts`.
3. Нажмите `Add file → Create new file`.
4. Назовите файл по шаблону `ГГГГ-ММ-ДД-название-latinicey.md`.

Пример: `2026-09-05-kak-gotovitsya-k-kontrolnoy.md`.

5. Вставьте шаблон:

```markdown
---
layout: post
title: "Как подготовиться к контрольной без ночного марафона"
description: "Короткое описание для списка статей и поисковиков."
category: "Учёба"
permalink: /articles/kak-gotovitsya-k-kontrolnoy/
image: /assets/articles/kontrolnaya.webp
image_alt: "Тетрадь с планом подготовки к контрольной"
image_caption: "Необязательная подпись к обложке."
---

Первый абзац: ситуация читателя и польза статьи.

## Первый содержательный вывод

Короткие абзацы. Конкретный пример.

## Что сделать сегодня

Один проверяемый шаг.
```

Если обложки нет, удалите строки `image`, `image_alt` и `image_caption`.

6. Нажмите `Commit changes` два раза.
7. Подождите 1–5 минут и откройте `https://indikov.ru/articles/`.

## 4. Добавьте иллюстрацию

Для обычной обложки:

- размер 1600×900 или 1600×1067;
- формат WebP или JPG;
- вес желательно 150–400 КБ;
- имя латиницей без пробелов: `kontrolnaya.webp`;
- папка `assets/articles/`.

После загрузки пропишите путь в поле `image`. Сайт покажет изображение в начале статьи и на карточке общего списка.

Для точной схемы с русским текстом используйте SVG, Figma или Canva. Генератор изображений лучше применять для сцен, метафор и атмосферных обложек: он может исказить буквы.

### Шаблон запроса для нейросети

```text
Создай журнальную иллюстрацию для статьи «[название]».
Главная мысль: [одна мысль].
Сцена: [кто, где, что делает].
Композиция: горизонтальная 3:2, важные детали не у краёв.
Стиль: спокойная современная редакционная иллюстрация, фактура бумаги.
Палитра: тёмно-синий, тёплый золотой, кремовый, немного шалфейного.
Без текста, букв, логотипов, водяных знаков и мистических символов.
```

Не просите нейросеть «нарисовать психологию». Опишите видимую сцену: «человек сравнивает две карты», «ученик проверяет решение тремя способами», «команда убирает лишние связи со схемы».

## 5. Проверьте материал перед публикацией

- Заголовок понятен без вводного абзаца.
- В первых трёх строках видно, для кого статья.
- Подзаголовки передают логику текста.
- Нет обещаний диагноза, гарантированного балла или универсального результата.
- У каждой важной мысли есть пример.
- Картинка имеет осмысленный `image_alt`.
- Все ссылки открываются.
- В конце есть одно действие, а не пять призывов сразу.

## Как исправить или снять статью

- **Исправить:** откройте `.md`-файл, нажмите карандаш, сохраните через `Commit changes`.
- **Снять с публикации:** удалите файл через меню GitHub. История сохранится, материал можно восстановить.
- **Подготовить черновик:** создайте текст вне `_posts`, например в папке `_drafts`; GitHub Pages его не покажет.

## Где всё хранится

Тексты и изображения находятся в репозитории GitHub. GitHub Pages собирает из них сайт. Отдельная база данных и отдельный хостинг для блога не нужны. Домен `indikov.ru` указывает на эту публикацию.
